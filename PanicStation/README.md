# Panic Station — онлайн-версия для своих

Частная браузерная версия настольной игры **Panic Station** (David Ausloos, White Goblin Games) для игры с друзьями (4–6 человек).
Все картинки взяты из фото нашей коробки и из PDF-правил. **Только для личного использования, никуда публично не выкладывать.**

## Что внутри архива

```
PanicStation/
├── panic_station.js      ← весь код: сервер + страница игры (один файл, без npm-зависимостей)
├── README.md             ← эта инструкция
└── assets/
    ├── img/              ← картинки, которые использует игра (карты, жетоны, комнаты, иконки)
    ├── docs/             ← оригинальные правила и памятки (PDF), открываются из игры кнопкой «Правила»
    └── source_photos/    ← исходные фото, из которых вырезаны картинки (игре не нужны)
```

Код ищет картинки в папке `assets` **рядом с собой**. Если `panic_station.js` прислали отдельным файлом —
просто положите его в папку `PanicStation/` (заменив тот, что там лежит, — это одно и то же).

## Запуск (нужен только Node.js 18 или новее)

```bash
cd PanicStation
node panic_station.js
```

В консоли появится `PANIC STATION запущен: http://localhost:3000`.
Ставить `npm install` не нужно — используются только встроенные модули Node.js.

Затем любой игрок открывает в браузере `http://<адрес-сервера>:3000`, вводит имя и нажимает **«Создать игру»**.
Появится код комнаты и ссылка — её нужно разослать остальным. Когда все зашли, создатель нажимает **«Начать игру»**.

### Игра за одним компьютером

На стартовой странице нажмите **«Играть за одним компьютером»**, впишите имена (2–6) и нажмите **«Начать игру»**.
Устройство передаётся по кругу: каждый раз, когда должен действовать другой игрок (его ход, выбор карты для обмена,
решение о бронежилете), экран закрывается шторкой «Передайте устройство игроку …». Игрок нажимает
«Я — …, показать мой экран» и видит только свои карты. Кнопкой «Вернуться к экрану …» предыдущий игрок может ещё раз
посмотреть результат своего действия, а потом закрыть экран кнопкой «Закрыть экран и передать».
В этом режиме нет чата, а на решение о бронежилете не даётся таймера.

### Настройки через переменные окружения (необязательно)

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `PORT` | `3000` | порт |
| `HOST` | `0.0.0.0` | на каком интерфейсе слушать |
| `ASSETS_DIR` | `./assets` рядом с файлом | где лежат картинки |
| `GAME_PASSWORD` | — | если задан, создать комнату можно только с этим паролем (поле «Пароль сервера» на стартовой странице) |

Пример: `PORT=8080 GAME_PASSWORD=secret node panic_station.js`

## Как открыть доступ друзьям

Любой из вариантов:

1. **VPS / сервер с белым IP** — запустить и открыть порт в файрволе. Чтобы работало постоянно:
   - `pm2 start panic_station.js --name panic` (если стоит pm2), или
   - systemd-юнит с `ExecStart=/usr/bin/node /path/PanicStation/panic_station.js` и `WorkingDirectory=/path/PanicStation`.
2. **За nginx (с HTTPS)** — обычный `proxy_pass`, но для потока событий нужно отключить буферизацию:
   ```nginx
   location / {
       proxy_pass http://127.0.0.1:3000;
       proxy_http_version 1.1;
       proxy_set_header Host $host;
       proxy_buffering off;          # важно для /api/stream (Server-Sent Events)
       proxy_read_timeout 1h;
   }
   ```
3. **Быстро, с домашнего компьютера** — туннель: `cloudflared tunnel --url http://localhost:3000` или `ngrok http 3000`, и разослать выданный адрес.

Связь с браузерами — обычный HTTP: действия идут POST-запросами, обновления — через Server-Sent Events (`/api/stream`). WebSocket не нужен.

## Важно знать

- **Состояние игр хранится в памяти.** Если перезапустить сервер — текущие партии пропадут (игроки увидят стартовый экран).
- Игрок, который обновил страницу или закрыл вкладку, возвращается в игру автоматически (сессия хранится в браузере).
- Скрытая информация (руки, кто заражён) не отправляется чужим браузерам — сервер шлёт каждому только его данные.
- Комнаты без активности дольше суток удаляются автоматически.
- Проверка, что сервер жив: `http://<адрес>:3000/health`.

## Что можно подправить в коде (в начале `panic_station.js`)

- `SEARCH_DECK` — состав колоды поиска (сколько каких карт). Точный состав коробки в правилах не указан, числа подобраны так, чтобы вместе с картой Носителя было 46 карт. Если в коробке иначе — поправьте.
- `EXPLORATION` — 20 карт комнат и расположение дверей на них (`D` — проход, `W` — стена, `S` — дверь безопасности). По фото двери видно плохо, поэтому раскладка придумана по мотивам оригинала.
- `AMMO_PER_CARD` — сколько патронов даёт карта патронов (на карте 4).

## Отличия от настольной версии

- Кубик D4 бросает сервер; тепловое сканирование считается автоматически (обмануть нельзя — как и по правилам).
- Если все паразиты уже на поле и нужно «призвать» ещё одного, сервер передвигает случайного (в настолке выбирает игрок).
- Нет правила «на руке всегда минимум 5 карт»: предметы можно разыгрывать при любом числе карт. Если игроку нечего отдать при обмене, обмен с ним не начинается.
- Следующая карта исследования всегда показана в левом верхнем углу поля. При исследовании на поле нарисованы все допустимые места и повороты карты (если подходят оба поворота — в клетке две уменьшенные карты, кликните нужную).
- Бронежилет предлагается сыграть автоматически, когда вас атакуют; на решение 45 секунд (в игре за одним компьютером — без ограничения).
- Горизонтальная выкладка Улья (крайний случай из правил) не поддерживается: если Улей некуда положить, берётся следующая карта; если Улей остался последним и его некуда положить — побеждают заражённые.
- В лобби есть три официальных варианта сложности из правил («полегче», «посложнее», правило для новичков-Носителей).
